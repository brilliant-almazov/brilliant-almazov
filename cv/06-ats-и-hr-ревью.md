# Ревью резюме: ATS-фильтр и живой HR

Два разных читателя, две разные проверки. Резюме должно пройти обоих подряд.

---

## Сначала главное: опыт сильный

Прежде чем про недостатки — трезво про исходный материал, потому что дальше идёт критика формы, а не содержания.

- **20 лет непрерывного стажа**, из них 10+ в продакшене. Никаких дыр в датах.
- **Со-основатель и CTO с экзитом.** На рынке сеньоров это редкость — большинство кандидатов никогда не отвечали за продукт целиком.
- **Реальный масштаб с числом:** 30K → 1.3M запросов в сутки на движок, 40× рост без переписывания.
- **Enterprise-логотипы:** Ozon, M.Video.
- **Три языка в продакшене:** Go, Rust, PHP. Не «изучал», а работающие системы.
- **Платформенный опыт целиком:** библиотека, control plane, sidecar, CI-эстейт, quality gates — то, что обычно делает выделенная команда из пяти человек.
- **Управленческий трек:** команда с 1 до 10, наём, менторство, on-call.
- **Публичный след:** три OSS-библиотеки и 16 опубликованных технических статей.
- **Экономический результат в деньгах:** 10× сокращение облачного счёта.

Это не «не самый широкий опыт». Это профиль, который в Израиле закрывает вакансию staff-уровня. Проблема была исключительно в упаковке: сильные факты лежали на третьей странице, слабые — в заголовке.

## Часть 1. ATS — машина

ATS (Applicant Tracking System — Greenhouse, Lever, Comeet, Workday) парсит файл в текст, вытаскивает поля и считает совпадение с описанием вакансии. Не понял файл — кандидат либо отсеян, либо попал к рекрутеру с половиной полей.

### ❌ Главная проблема текущего файла

`Profile (3).pdf` — это экспорт LinkedIn: **две колонки и тёмный сайдбар слева**.

Это классический ATS-киллер. Парсер читает страницу построчно слева направо и склеивает две колонки в один поток. На выходе получается каша вида `0557720204 (Home) Anton Brilliantov brilliantov.anton@gmail.com Senior Backend & Platform Engineer`. В сайдбаре при этом лежит всё важное: контакты, Top Skills, языки, сертификаты — и именно это теряется чаще всего.

**Действие: одна колонка. Всегда. Никаких сайдбаров.**

### Чек-лист формата

| Правило | Почему |
|---|---|
| **Одна колонка**, без таблиц, текстбоксов, колонтитулов | Многоколоночная вёрстка и таблицы парсятся в мусор |
| **Контакты обычным текстом в самом верху тела**, не в header страницы | Содержимое header/footer многие парсеры не читают вовсе |
| **DOCX для подачи**, PDF — когда просят PDF | DOCX парсится точнее; PDF безопасен, только если он текстовый, а не картинка |
| **Стандартные заголовки разделов:** `Summary`, `Experience`, `Skills`, `Education`, `Certifications` | Парсер ищет буквально эти слова. `What I bring`, `Career timeline`, `Stack & impact` он не опознаёт |
| **Даты в формате `MM/YYYY – MM/YYYY`** или `Jun 2013 – Aug 2021`, единообразно | Разнобой ломает вычисление стажа |
| **Должность отдельной строкой**, потом компания, потом даты | Порядок `Title / Company / Dates` — самый распознаваемый |
| Никаких иконок, эмодзи, графиков, шкал навыков, фото | Всё это либо игнорируется, либо ломает поток текста |
| Шрифт обычный (Arial, Calibri, Helvetica), 10–12 pt | Экзотика иногда извлекается с битой кодировкой |
| Имя файла: `Anton-Brilliantov-Senior-Backend-Engineer.pdf` | Часто попадает в карточку кандидата и читается человеком |

### ❌ Что в текущем резюме ломает парсер отдельно

1. **Заголовок-абзац под именем.** Поле `Title` парсер берёт из первой строки после имени. Сейчас туда попадает `Senior Backend & Platform Engineer · Go · Rust · PHP · PostgreSQL · BigQuery — AI-augmented at senior scale: 6,300+ commits, 3.4M LOC…`. В карточке кандидата это выглядит как мусор.
2. **Разделитель `·` вместо запятых** в перечислениях стека. Часть парсеров не разбивает по `·` и сохраняет весь список одной строкой — совпадений по ключевым словам меньше.
3. **`3.4M LOC`, `6,300 commits`** занимают место, где должны стоять ключевые слова, по которым идёт скоринг.
4. **Секция `Achievements` внутри `Summary`** — парсер ждёт `Summary` коротким, а перечисление достижений видит как продолжение профиля и обрезает.

### Ключевые слова, которых не хватает

По этим словам ищут на позиции, куда ты идёшь. Каждое должно встречаться в резюме **в контексте, а не списком**:

```
Distributed Systems · Microservices · System Design · Software Architecture
Scalability · High Availability · Performance Optimization
Event-Driven Architecture · Message Queues · Kafka · RabbitMQ · NATS
REST API · gRPC · API Design · Backend Development
PostgreSQL · MySQL · Redis · SQL · NoSQL · Data Pipelines · ETL · BigQuery
CI/CD · Docker · Kubernetes · GCP · AWS · Observability · Monitoring
Go · Golang · Rust · PHP · Symfony · TypeScript · Node.js*
Technical Leadership · Mentoring · Code Review · Agile
```

⚠️ **`Golang` пишется отдельно от `Go`.** Половина рекрутеров ищет именно `Golang`, и совпадения по `Go` не будет. Вписать оба варианта: `Go (Golang)`.

\* `Node.js` — только если появится реальный опыт. Врать нельзя: это отсеивают на первом же техническом звонке.

## Часть 2. Живой HR — 8 секунд

Пройдя ATS, резюме попадает человеку, у которого стопка. Он смотрит по F-образной траектории: верхняя треть первой страницы, потом левый край вниз, потом иногда вторая страница.

### Что должно попасть в верхнюю треть

| Слот | Что там сейчас | Что должно быть |
|---|---|---|
| Строка под именем | абзац с LOC и коммитами | `Senior Backend & Platform Engineer — Distributed Systems, Real-Time Data at Scale` |
| Локация | `Israel` | `Ramat Gan, Israel` (гео-фильтр рекрутера — по округу) |
| Первые две строки summary | «Passionate about clean, correct code» | экзит + масштаб + текущая роль |
| Первый факт | нет | `Co-founder & CTO of a SaaS, scaled 30K → 1.3M queries/day, exited 2021` |

### Красные флаги, которые HR ловит машинально

| Флаг | Статус |
|---|---|
| Нахлёст дат (`Analyzit` ∥ `Stealth`, `404group` ∥ `Seowork`) | ✅ снято: `Part-time` проставлен, `404group` удалён |
| `English (Limited Working)` | ✅ снято: `Professional working` |
| Расхождение резюме и LinkedIn | ⚠️ **чинится вручную** — см. `05-linkedin-по-блокам.md` |
| Компания не названа (`Stealth Startup`) | ok, если названы индустрия и роль — они названы |
| Нет причин ухода / нет дыр | ✅ дыр нет вовсе, 20 лет подряд |
| Резюме длиннее двух страниц | ⚠️ следить при вёрстке: две страницы максимум |

### Чего HR ищет глазами и не находил

- **Цифры.** Сейчас их две (1.3M и 10×). Должно быть 8–10 по всему документу.
- **Размер команды.** «Led backend team» без числа не считается. `up to 6`, `grew from 1 to 10` — считается.
- **Длительность в цифрах.** `8 years` рядом с датами: рекрутер не считает в уме.
- **Слово `exited`.** Один из немногих маркеров, который мгновенно поднимает кандидата над стопкой.

## Часть 3. Что сделать по шагам

1. **Взять `07-CV-ats-safe.md`** — это версия под ATS: одна колонка, стандартные заголовки, `Go (Golang)`, без таблиц и символов-разделителей.
2. **Сверстать в Google Docs или Word** обычным шрифтом, одной колонкой. Экспорт в DOCX и в PDF.
3. **Проверить парсинг:** открыть PDF, выделить всё, скопировать в блокнот. Прочитать получившийся текст. Если он читается как связное резюме — ATS справится. Если колонки перемешались — вёрстка плохая.
4. **Под каждую вакансию** — открыть описание, выписать 10–15 повторяющихся терминов и убедиться, что каждый встречается в резюме в осмысленной фразе. Не списком в конце: современные ATS понижают ранг за очевидную набивку ключевых слов.
5. **Привести LinkedIn** к тому же таймлайну (`05-linkedin-по-блокам.md`). Рекрутер сверяет — это первое, что он делает после ATS.
